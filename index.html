eMAS Industrial Agent

Autonomous factory intelligence & API orchestration

eMAS is an industrial AI system that connects an AI chatbot with factory operations. It uses a Go REST API and a Python FastAPI agent service to process user requests, retrieve safety documents, and call backend tools safely. The system uses LangGraph-style workflows, hybrid RAG, and deterministic guardrails to support safe AI-assisted factory operations.

Key Highlights
  • Go Backend: Handles factory data, business logic, and API operations.
  • OpenAPI Tooling: Lets the AI agent understand and call backend APIs safely.
  • AI Agent Workflow: Uses LangGraph-style flow for multi-step planning, retries, and recovery.
  • RAG Retrieval: Uses ChromaDB and hybrid search to retrieve safety documents and SOPs.
  • Safety Guardrails: Checks AI-proposed actions before they run.
  • Two-Step Write Flow: Stages changes first, validates them, then commits safely.
  • Prompt Testing: Uses Promptfoo to test prompt accuracy and safety.
  • Tracing & Monitoring: Uses LangSmith to debug agent steps, latency, and failures.
  • Live Streaming: Shows agent reasoning and tool execution progress in real time.

Go API · Flutter client Completed

Song Clash

Music clip quiz platform & multiplayer game

A split stack for a “guess the song / artist” experience: a Go backend owns song catalogs, filtering, random clip selection, multiplayer rooms, and real-time play over WebSockets—while a Flutter client delivers solo, 1v1, and room-based modes with timed rounds, audio preloading, and localization. Operators can build clip libraries from YouTube via a Python + ffmpeg pipeline, with optional Google Drive hosting for MP3s and local text catalogs for metadata—so clients focus on UX while the API owns catalog, randomization, and room lifecycle.

Key Highlights
  • Backend: REST API for songs/artists—filters by language, year, range, artist; random unique picks; health & CORS.
  • Rooms: create/join/leave, host actions (start, kick), room/game state, delete room; WebSocket hub (gorilla/websocket) at /rooms/{roomId}/stream.
  • Pipeline: Python + yt-dlp + ffmpeg for 15s clips; Language/Year folder layout; Drive integration when folder ID / API key are set; QC scripts (verify, silent-clip checks, sync helpers).
  • Flutter game: Solo, 1v1, and multiplayer with waiting room; guess song name or artist from the same clip loop.
  • Audio & sync: audioplayers + preload for next clip, countdown, fallbacks (web behavior documented in-repo); WebSocket room coordination with HTTP for room/song APIs.
  • Localization & architecture: English, Chinese, and Japanese; Provider + services (song_data, room, realtime_room, audio); Android, iOS, and web from one codebase.
  • Deploy: production API at https://song-clash-api.onrender.com (overrideable for local dev).

  • Read receipts and unread counts (WhatsApp-style ticks on web)
  • REST API + Swagger at /swagger/index.html
  • Responsive web (Next.js + Tailwind + Framer Motion) and React Native (Expo) clients
